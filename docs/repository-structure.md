# 仓库目录与文章维护约定

## 系列与编号

- 根目录按主题设置系列目录，例如现有 `ROCmArticle/`。新项目可以加入相关系列；主题相差较大时新增并列系列，名称采用简短、稳定的英文主题名加 `Article`。
- 每个系列维护自己的 `README.md`，记录文章索引、状态与后续选题。
- 每篇文章使用 `三位编号-主题` 作为目录名，例如 `001-双项目1.0正式发布/`。编号在系列内递增、独立分配。
- 编号与路径一旦使用即保持稳定。阅读顺序通过索引调整，不通过批量改名调整；尚未动笔的选题不提前占号。
- 涉及多个项目的文章保留一份主文件，在其他系列索引中链接，不复制多份正文。

## 单篇文章

```text
001-文章主题/
├── 00-文章规划.md
├── 01-事实与来源.md
├── 02-配图方案.md
├── 03-正文.md
├── 03-正文预览.html     # 按需生成
├── 04-编辑记录.md
├── assets/             # 图片及文章运行所必需的小型资源
├── examples/           # 可运行的配套示例
└── research/           # 来源、提示词、验证与历史修订
```

简单文章可以按需精简资料文件；`03-正文.md` 始终是阅读与编辑主文件。模板见 [templates/article/README.md](../templates/article/README.md)。

## 索引与状态

根目录 README 负责跨系列导航；系列 README 负责系列内排序和状态。新增文章时同步更新两级索引。

建议状态为：规划、草稿、待核对、可发布、已发布。GitHub 源码上传与对外平台发布分开记录；平台发布后，在编辑记录中补充地址和日期。

## 配图、链接与素材

- 优先使用文章内相对路径，保证克隆仓库后可以阅读。作者已有在线托管地址时保持原样，不重复迁移。
- 已认可的文章图片和托管地址，只在明确需要调整时修改；更新文字或标题不重生成配图。
- 文章正文的外部链接使用代码块或行内代码，表格直接展示 URL 文本。仓库导航可以使用普通 Markdown 链接。
- 可追溯的生成提示词、原图和必要验证资料可以保留；不提交 API 密钥、本机环境配置、依赖缓存、构建目录或大型数据集。
- 图片以单篇目录管理，暂不迁移到全仓库共享图片目录，避免后续修改破坏已有文章链接。

## 项目源码与许可

文章仓库存放介绍、示例和必要资料，完整项目源码通过已核实的项目仓库链接引用。项目名、目录名、包名和版本号应分别核对。

文章及配图的授权由作者决定；第三方材料保留来源与许可信息，不沿用被介绍项目的许可来覆盖文章本身。
