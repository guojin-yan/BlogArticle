## 输入核验与截图方式

重新读取 UCI 官方 ZIP 的 `PS1.txt` 第 1 行，与 CSV 的 6,000 个原始数字字符串逐项比较，确认未缩放、未重采样、未拼接。重新读取 VisA 官方 TAR，12 个上传 JPG 与对应成员的 SHA256 全部一致。完整归档 SHA、逐样本哈希及核验范围见 [真实输入核验](validation/round4/inputs/real-input-audit.json)。归档哈希为本地实测身份，不是发布者数字签名。

最新 OCR 演示从另一张真实照片 `b533107ff30932da` 中裁出白底 APPLE / SODA 招牌，使用官方两行原文与行框，模型和前处理不变；两行实际 GPU 输出均一致。本轮未新增 CPU 概率张量对照。选图是为了直观展示，不是随机精度评测，不含文字检测或票据字段验收。

第五轮复杂街景的完整 24 行及19行失败仍保留在[历史对照报告](validation/round5/document-hiertext-native-path/evidence.html)，没有覆盖或改写；当时的 CPU/GPU 概率张量对照和评分也不挪作新图片的结果。

视频先查看原视频 30 秒位置，确认已过片头且存在人物活动，再写入 [固定协议](validation/round4/video-protocol.json)，之后才推理；没有根据预测挑选成功帧、改变置信度或事件阈值。NASA 是公开媒体素材，不能套用案例源码的 Apache-2.0，也不暗示 NASA 认可项目。没有独立人工事件标注，不报告事件精确率或召回率。

正文使用第五轮另外三例截图与第六轮简单 OCR 截图，均由浏览器接口直接绑定实际 URL、回读地址后保存原始 JPEG 字节。SurfaceLab 是真实工作台；Signal / Video 是应用 HTML；OCR 是从本轮原始输出生成的简洁证据报告。**不是全桌面或终端截图**，未补框或改写预测。尺寸、日期、URL、哈希和证据映射见[第五轮清单](validation/round5/screenshots/manifest.json)与[第六轮 OCR 清单](validation/round6/screenshots/manifest.json)。原先无法识别 Edge URL 的辅助工具没有宣称修复，本任务使用能可靠核对 URL 的浏览器接口。

## 失败与资料版本

第五轮原生 C API 单变量对照将故障定位到本机 `HIPBLASLT_TENSILE_LIBPATH` 的正斜杠/混合分隔符。改用 Windows 反斜杠后，MatMul、SurfaceLab 模型和 HierText OCR 均完成编译与运行，读者包装脚本已修正；不改变模型或阈值。内部源码级缺陷尚未定位，不外推到所有引擎版本。Video 退出 0，但 stderr 的 `hipErrorInvalidKernelFile` / MIOpen 诊断仍存在，作为独立现象保留。

文档输出仍使用临时盘符别名指向文章证据目录，适配器只保留该逻辑路径，以满足应用拒绝在任意 Git 祖先目录写输出的规则；所有物理文件仍在文章目录。原始官方标注校验、模型调用与评分沿用应用 evaluator。这不是未经调整编排的独立读者安装测试。结束后解除别名。

复用固定提交 `2f70b96267484b441fa726a3d496b8cc55d47219` 的只读源码快照和构建 DLL，未改三个正式源码仓库。264 项测试与性能结果仍按原日期记载；MatMul 本轮实际复跑。环境为 Windows 11 / W7900 gfx1100 / ROCm 10.1 / MIGraphX 2.18，二进制身份与编译对照见第五轮清单。

简单 OCR 新资料只放 `round6`，`round2` / `round3` / `round4` / `round5` 原始文件及清单不覆盖。旧正文等文件分别按 `a5aeb7d` / `a4f73e4` / `9727a7d` / `1b33655` 核对。见[简单 OCR 记录与署名](validation/round6/README.md)，另外三例沿用[第五轮目录](validation/round5/README.md)及[第三方署名](validation/round5/THIRD_PARTY.md)。全部历史失败仍原样保留。
